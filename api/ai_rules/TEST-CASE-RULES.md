# 测试用例扩展设计规则（NAS云存储增强）

本文档定义 **功能测试之外的扩展维度** 与 **设计阶段检查清单**，供 `skills/test-cases/SKILL.md` 在 Phase 2、Phase 2.8 执行缺口扫描。与核心 4 法（EP/BVA/ST/EG，见 [TEST-DESIGN-METHODS.md](TEST-DESIGN-METHODS.md)）叠加使用，**不改变** 9 维质量门禁的数值阈值。

> 产品语境：本仓库优先服务 **NAS 云存储 / 文件管理 / 多端同步** 类产品。扩展维度检查必须重点关注文件数据安全、权限隐私、多端同步、共享协作、大文件/批量/并发、容量与系统依赖、异步索引/转码/AI 等风险。

---

## NAS 云存储产品扩展覆盖范围

Phase 2 与 Phase 2.8 必须重点扫描以下范围：

| 范围 | 检查重点 |
|------|----------|
| 文件与目录操作 | 上传、下载、复制、移动、重命名、删除、恢复、预览、搜索、排序、筛选 |
| 数据完整性 | 文件内容、大小、哈希、缩略图、转码结果、修改时间、标签、元数据、路径索引 |
| 权限与共享 | 私有目录、成员权限、分享链接、提取码、有效期、只读/可编辑权限 |
| 多端同步 | Pc / Web / Android / IOS 之间的状态同步、冲突处理、离线恢复 |
| 大文件与批量操作 | 断点续传、批量删除/移动/恢复、深层目录树、部分成功/部分失败 |
| 存储与系统状态 | 容量不足、磁盘异常、索引延迟、服务降级、网络中断 |
| 异步处理 | 缩略图、转码、搜索索引、AI 分析、后台任务队列 |
| 升级与兼容 | 应用升级、数据迁移、历史文件、旧权限模型、旧索引数据兼容 |

---

## 设计原则

| 原则 | 说明 |
|------|------|
| **全面性** | 功能、边界、异常、性能、兼容性、安全、可用性等多维度 |
| **层次性** | P0 核心 / P1 重要 / P2 一般 / P3 边缘（分布见 [TEST-PRIORITY.md](TEST-PRIORITY.md)） |
| **可执行性** | 前置条件明确、步骤可操作、预期结果可验证 |
| **效率性** | 用最少用例覆盖最多场景；语义重复须合并 |
| **数据安全性** | 文件不得丢失、损坏、误删、越权访问或泄露 |
| **一致性** | 列表、详情、搜索、预览、容量统计、多端展示应保持一致 |
| **可恢复性** | 中断、失败、冲突、部分成功后，系统应可重试、可恢复、可追踪 |

## 补充测试设计方法

在 EP→BVA→ST→EG 之后，按需求特征选用：

| 方法 | 适用场景 | 动作要点 |
|------|----------|----------|
| **状态迁移** | 文件上传、下载、删除、回收站、分享链接、同步任务、AI 分析 | 覆盖合法迁移、非法迁移、终态、失败态、恢复态 |
| **数据流测试** | 文件内容、元数据、权限、标签、搜索索引、缩略图、容量统计跨模块传递 | 验证上传/删除/移动/权限变更后，各入口数据一致 |
| **探索式测试** | 多端、多用户、弱网、大文件、批量、并发、长时间任务 | 从时间/空间/组合/极端操作维度补充高风险场景 |

> 补充方法不替代 EP/BVA/ST/EG。若下游平台暂只识别核心 4 法，可将状态迁移与数据流测试写入 `备注`，或归入 `ST` / `EG` 组合标记。

## 3.1 功能性覆盖检查清单

### 通用功能性检查

- [ ] 覆盖所有需求点（正向路径）
- [ ] 边界值输入（最小值、最大值、空值、特殊字符）
- [ ] 异常场景（非法参数、无效数据、缺少依赖条件）
- [ ] 完整端到端业务流程
- [ ] 分支逻辑与不同条件下的路径
- [ ] 流程中断、异常回滚后的系统状态
- [ ] 平台特点的操作流程
- [ ] 多地域/多配置（云端、NAS、不同存储卷等）
- [ ] 不同数据量级（空、少、大、海量）
- [ ] 数据一致性、正确性、完整性

### NAS 功能性补充检查

- [ ] 文件上传、下载、复制、移动、重命名、删除、恢复主流程
- [ ] 文件夹/目录操作：新建、重命名、移动、删除、深层目录、空目录
- [ ] 文件预览：图片、视频、PDF、文本、未知格式、转码失败降级
- [ ] 搜索与筛选：文件名、标签、类型、时间、路径、权限过滤、索引延迟
- [ ] 标签/分类：创建、编辑、删除、绑定、解绑、数量限制、颜色/排序
- [ ] 分享：创建链接、取消分享、提取码、有效期、权限范围、文件被删除后的访问
- [ ] 权限：所有者、管理员、只读成员、可编辑成员、访客、权限变更即时生效
- [ ] 多端同步：一端操作后，另一端列表、详情、搜索、容量统计同步
- [ ] 回收站：删除、恢复、彻底删除、过期清理、原路径不存在、同名冲突
- [ ] 容量统计：上传、删除、恢复、清空回收站后容量变化准确
- [ ] 异步任务：索引、缩略图、转码、AI 分析的处理中、成功、失败、超时降级

### 文件类型覆盖策略

| 类型 | 关注点 |
|------|--------|
| 图片 | 缩略图、预览、EXIF、超大分辨率、损坏图片 |
| 视频 | 转码、封面图、播放失败、超大文件、断点播放 |
| PDF/文档 | 在线预览、转码失败、权限控制、下载回退 |
| 压缩包 | 预览/解压能力、超大压缩包、嵌套目录 |
| 文本/代码 | 编码、换行符、超大文本、特殊字符 |
| 未知类型 | 图标展示、下载能力、不可预览提示 |
| 0 字节/损坏文件 | 上传限制、预览降级、错误提示 |

## 3.2 健壮性检查清单

### 通用健壮性检查

- [ ] 操作中途退出 / 刷新 / 网络中断 / 断电恢复
- [ ] 本地缓存保存与恢复
- [ ] 同操作重复执行、重复提交、死循环
- [ ] 内存泄漏风险（长会话、大批量）
- [ ] 跨类型输入、格式不合法数据的错误提示

### NAS 健壮性补充检查

- [ ] 上传/下载/移动/删除过程中断网、刷新、关闭客户端、设备休眠
- [ ] 大文件断点续传：暂停、恢复、失败重试、断点过期、重复分片
- [ ] 批量操作部分成功/部分失败：结果明细、可重试、不可产生脏状态
- [ ] 同名冲突：上传、移动、恢复、重命名时冲突处理符合规则
- [ ] 权限变化中断：操作过程中权限被取消或降级
- [ ] 多端并发冲突：多个客户端同时重命名、移动、删除同一文件
- [ ] 缓存与离线恢复：离线操作、重新联网、客户端缓存与服务端状态一致
- [ ] 异步任务失败：索引、缩略图、转码、AI 分析失败后有降级展示
- [ ] 容量变化中断：上传、复制、恢复过程中容量被占满或配额被调整
- [ ] 服务降级：存储、索引、预览、AI 能力不可用时主流程有可理解反馈

## 3.3 非功能性检查清单

### 性能

- [ ] 大文件上传/下载吞吐达到需求或基线
- [ ] 批量操作在指定数量内响应可接受
- [ ] 大目录列表加载、分页、排序、筛选不卡顿
- [ ] 搜索索引更新延迟有明确预期或提示
- [ ] 图片/视频/PDF 预览加载超时有降级
- [ ] 多用户并发上传/下载时系统稳定
- [ ] 长时间任务不导致客户端明显卡顿、内存持续增长或页面无响应

### 兼容性

- [ ] Pc / Web / Android / IOS 操作能力差异符合需求
- [ ] 不同浏览器下载、拖拽上传、文件夹上传表现一致或差异有说明
- [ ] 不同 OS 文件名非法字符、路径分隔符、大小写规则处理正确
- [ ] 移动端后台切换、锁屏、网络切换后任务状态正确
- [ ] 老版本客户端、旧索引数据、历史权限模型在升级后仍可用或有兼容策略

### 安全

- [ ] 无权限用户不可访问私有文件、目录、缩略图、预览地址、下载地址
- [ ] 分享链接过期、取消、权限变更后立即失效
- [ ] 只读用户不可通过页面或接口执行写操作
- [ ] 搜索结果不泄露无权限文件名、路径、缩略图
- [ ] 日志不记录敏感文件名、提取码、访问 token、私有下载地址
- [ ] XSS/SQL 注入等输入安全风险已覆盖，尤其是文件名、标签名、搜索词、分享备注

### 可用性

- [ ] 文案与错误提示友好，能指导用户恢复操作
- [ ] 上传、下载、批量任务有清晰进度、成功/失败状态和失败原因
- [ ] 空目录、无搜索结果、无权限、链接过期等空态有明确说明
- [ ] 高风险操作（删除、彻底删除、取消分享、权限变更）有确认或可撤销机制

### NAS/升级

- [ ] 应用与数据升级后，历史文件、标签、分享、权限、索引仍可用
- [ ] 极端数据量升级性能可接受，并有失败恢复策略
- [ ] 升级后文件列表、搜索、容量统计、回收站、共享链接一致
- [ ] 升级过程中断电/断网/重启后可恢复，不产生不可访问文件或脏数据

| 维度 | NAS 示例 |
|------|----------|

- [ ] 日志追踪 ID、健康检查、Mock/桩支持

- [ ] 服务降级、重试、失败恢复有日志或状态码可追踪

## 3.6 风险与易测性

### 通用风险检查

- [ ] 核心链路、升级、权限、外部依赖、弱网
- [ ] 历史高发缺陷回归点
- [ ] 与「风险点」模块类别对齐（见 test-cases Skill Phase 3）

### NAS 风险类别建议

生成用例时，「风险点」模块第二层风险类别可优先使用：

| 风险类别 | 典型风险 | 建议验证方向 |
|----------|----------|--------------|
| 数据完整性 | 文件丢失、损坏、重复、版本错乱、元数据不一致 | 上传/移动/删除/恢复后校验内容、路径、大小、哈希、元数据 |
| 权限与隐私 | 越权访问、私有文件泄露、只读用户写入 | 页面入口 + 接口访问 + 真实下载/预览结果 |
| 多端同步 | 一端操作另一端不可见、状态滞后、冲突未提示 | 明确操作端和观察端，验证列表/详情/搜索/容量一致 |
| 大文件与批量 | 断点续传失败、批量部分失败、长任务不可恢复 | 验证进度、失败明细、重试、恢复、无脏状态 |
| 容量与存储状态 | 容量不足、磁盘异常、配额变化导致异常 | 验证提示、阻断、残留清理、容量统计 |
| 分享外链 | 链接过期仍可访问、取消分享未生效 | 验证有效期、提取码、权限变更、文件删除后的访问 |
| 索引与搜索 | 搜索结果延迟、权限过滤错误、旧路径脏数据 | 验证索引状态、无权限过滤、移动/删除后结果更新 |
| 缩略图/转码/预览 | 转码失败白屏、缩略图错误、预览泄露 | 验证降级展示、原文件可下载、权限控制 |
| AI/外部依赖 | AI 超时、无结果、结果不稳定、服务不可用 | 验证超时阈值、空结果、降级文案、可重试 |
| 弱网与中断恢复 | 断网、刷新、关闭客户端导致任务状态错乱 | 验证暂停、恢复、失败态、最终一致性 |
| 升级与兼容 | 旧数据不可访问、旧权限/索引失效 | 验证升级前后核心链路与历史数据 |

**强制要求**：每个已识别风险类别至少应有 1 条可执行用例进入 `模块` 路径：

```json
["风险点", "<风险类别>"]
```

不得仅生成一层 `"风险点"`，也不得将风险用例只混入功能模块末级而不建立风险类别。

## 多端差异检查

当标签包含多个端时，需检查：

- [ ] Pc / Web / Android / IOS 是否存在能力差异
- [ ] 文件夹上传、拖拽上传、后台下载、分享入口等是否仅部分端支持
- [ ] 同一操作在不同端的文案、状态、错误提示是否一致
- [ ] 一端操作后其他端是否同步刷新
- [ ] 移动端后台切换、锁屏、网络切换后的任务状态
- [ ] 端能力差异是否已在用例前置条件或备注中说明，避免错误判定

---

## 扩展维度去重规则

- 不因“不同端展示”重复生成相同验证目标，除非端能力或同步规则不同。
- 不因“不同文件类型”重复生成相同操作用例，除非预览、转码、权限或处理逻辑不同。
- 不因“不同数据量”重复生成相同功能用例，除非性能、分页、批量、容量、超时等验证目标不同。
- 不因“混合场景”重复生成已覆盖的核心断言，除非组合后产生新的风险。
- 不因“不同角色名称”重复生成权限用例，除非权限边界或可执行操作不同。
- 判断是否重复时，以**验证目标**而非**测试数据/前置状态是否不同**为准。

## 多视角评审（Phase 2.8 必做自检）

生成预览前，从以下视角快速审视是否有关键缺口。发现 P0/P1 缺口时，必须回到 Phase 2 补全后再展示预览。

| 视角 | 关注 |
|------|------|
| **专业测试** | 覆盖度、有效性、可执行性、无冗余 |
| **产品经理** | 文件管理场景完整、用户体验、文案、异常提示 |
| **资深开发** | 状态机、异步任务、并发、缓存、索引、事务一致性 |
| **安全视角** | 权限、分享外链、越权、敏感信息泄露 |
| **运维/系统视角** | 存储容量、磁盘状态、服务降级、日志追踪、健康检查 |
| **多端用户视角** | Pc / Web / Android / IOS 同步一致性、冲突提示 |
| **风险把控** | 数据丢失、误删、泄露、升级兼容、历史缺陷 |

## 设计注意事项

1. **不做工作量估计**：专注于用例设计本身。
2. **重视用户体验**：不仅是功能正确性。
3. **效果类 / AI 类功能**：预期结果尽量可量化（准确率区间、超时降级、空结果提示等）。
4. **历史影响**：对现有功能、升级路径、数据迁移的兼容性。
5. **能够量化的要量化**：避免「正常」「正确」等模糊预期。
6. **文件数据不可丢失**：涉及上传、删除、移动、恢复、同步的用例，预期结果必须验证文件内容、路径、状态和元数据。
7. **权限不可只测页面入口**：权限类用例必须验证接口或真实访问结果，避免只检查按钮隐藏。
8. **跨端一致性要有观察端**：多端同步用例应明确操作端和观察端。
9. **异步任务要覆盖中间态和失败态**：索引、缩略图、转码、AI 分析不能只测成功态。
10. **批量操作要验证明细**：批量部分失败时，应验证成功项、失败项、错误原因和重试能力。
11. **容量与存储状态要验证结果一致性**：上传、删除、恢复、清空回收站后应验证容量统计与文件状态一致。
12. **风险点必须模块化**：风险相关用例必须进入 `风险点 → 风险类别` 路径，不能仅在备注中说明。

## Phase 2.8 缺口扫描输出要求

对每个扩展维度给出以下之一，写入预览摘要：

- **已覆盖**：列出代表用例数或模块
